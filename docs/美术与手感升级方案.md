# 主角与僵尸：美术 + 手感升级方案

> 起草人：ZCode ｜ 适用版本：`dcff133` ｜ 前置约束：**零素材、零依赖、纯 Canvas 2D 程序化生成**（README 的承诺）

---

## 0. 一句话结论

现在不好看，**不是"渐变不够多"或"细节不够足"，而是三个更根本的问题**：

1. **头与肩的关系没设计** —— 头过大（0.42R）且与躯干同明度、几乎重叠，中间没有分离边；肩只是两个椭圆鼓包。俯视角下一眼能读出的信息就是"头 + 肩"这两块，它们糊在一起，整只怪就糊了。
2. **是"拼"出来的，不是"设计"出来的** —— 全身由 ~15 个软边椭圆/胶囊（`volumeEllipse` / `volumeLimb`）堆叠，没有一条硬边。放大 6 倍是"模糊的橡皮泥"，缩到游戏里的 28–48px 就糊成一团。手臂更是细长杆贴着脑袋两侧伸出、末端挂亮球，读成"兔耳/钳子"。
3. **明度没有分层 + 卡通五官** —— 躯干、头、肩、手臂几乎同一个明度；脸是一对高饱和大红眼加一张大嘴（表情包语法）。小尺寸下能读出的信息量 = **外轮廓 + 2~3 个明度带 + 1 个强调色**，现在就剩"一坨中间调"。

结论：**先重构剪影与明度，再谈细节**。加细节在这个尺寸下是浪费，甚至会让它更糊。

## 1. 现状诊断（有实证，不是感觉）

放大 6 倍的对照图：`.zcode-smoke/shots/art-closeup.png`（工具 `art-closeup.mjs`，可随时重跑）。

> ⚠️ **本条诊断的第一版是错的，已更正。** 最初我用出图工具直接画了未旋转的精灵，看到"手在头顶之上"，
> 于是判断成"俯视游戏用了正面造型 / 举手投降姿势"。**这个结论不成立**：精灵一律按「面朝 -Y」绘制，
> 游戏内 `ctx.rotate(a + Math.PI/2)` 把 -Y 对齐到朝向，所以手臂本来就是**朝前伸**的、腿也是沿朝向
> 前后迈步 —— 构造其实已经是俯视的。错在**工具**：它漏了那一步旋转，我看到的是"躺着的"角色。
> 工具已修（现在按游戏内朝向出图 + 一条朝向箭头）。教训：**看图判断姿势之前，先确认你看的是不是
> 游戏里的那个变换** —— 否则会把"工具没旋转"误读成"美术画错了"。

修正后的真实成因（三条，都是小尺寸下的可读性问题）：

### 1.1 头太大、紧贴躯干，两个球糊成一个
`drawZombiePose` 里躯干是一颗 `R*torsoW × R*torsoH` 的软渐变椭圆，头心在 `Y(-0.5)`、头部半径 `0.42R` ——
躯干前缘与头部几乎重叠，且两者**同明度**，中间没有任何分离边。小尺寸下这是"一坨"，不是"一个人"。

### 1.2 手臂又长又细、贴着脑袋两侧伸出，末端挂亮球
`armLen` 默认 1.3（头才 0.42），而 `aL/aR` 只有 0.32/0.44 —— 两条细杆几乎贴着中轴、比头还靠前，
末端是提亮 40% 的圆球。放大图里就是"两根钳子/兔耳夹着一个大头"。

### 1.3 全软渐变 + 卡通五官
- 全身用 `volumeEllipse` / `volumeLimb` 的**径向渐变**堆出来，没有任何硬边：放大是橡皮泥，
  缩到实际显示尺寸（28–48px）就是糊。
- 脸是**表情包语法**：两个高饱和大红眼 + 一张几乎盖住下半张脸的暗色大嘴。发光本该是稀缺资源。
- 主角的武器只是 `render.js` 里一根矩形 + 一个小凸起，读不出"这是把枪"。

### 1.4 根本原因
缺了「造型设计」这一步：现在是**给定归一化半径 R，往 `Y(-1.06)`、`X(±0.80)` 这些坐标上放体块**。
这套流程能做出"认得出是什么"，但做不出"好看" —— 因为**没有人在设计剪影与明度**，只是在填参数。

## 2. 技术路线：2D 里性价比最高的五件事

> 原则：**在 28–48px 的显示尺寸下**，可读性来自「剪影 → 明度 → 硬边 → 动作 → 特效」，细节排在最后。所有方案都保持零素材、可程序化生成。

### 2.1 头 / 肩 / 臂的关系修正（收益最大，改动最集中）

俯视角下**头与肩的关系**才是识别核心。构造本身已经是俯视的（-Y 是"前"），要改的是比例与分离：

| 部件 | 问题（改前） | 做法（已落地） |
|---|---|---|
| 头 | 半径 0.42R，与躯干同明度且几乎重叠 | 缩到 0.28–0.34R，外面套一圈**更暗的颅骨外圈**把头"切"出来；头颅用与躯干同族的色，只有**颅顶**受光 |
| 肩 | 只是躯干两侧的椭圆鼓包 | **两块外扩的斜方板**（从肩线斜向外下）—— 有没有它，一眼差一档 |
| 手臂 | `armLen` 1.3、`aL/aR` 0.32/0.44：细长杆贴着脑袋、末端亮球 | `reach` 封顶 0.95、手臂加粗、`aL/aR` 外扩到 0.44–0.60、手改成**暗一档的小圆** |
| 躯干 | 软渐变椭圆 | **硬边路径**（肩宽→后收）+ 暗底/受光面两级明度 + 破洞裁进路径内 |
| 腿 | 只有前后摆，看不出抬脚 | 沿朝向迈步 + **抬脚项**（顺带保证 4 帧互不相同） |
| 武器 | 一根矩形 + 小凸起 | **四段式剪影**：枪托 / 机匣 / 顶部导轨（唯一亮面）/ 弹匣 / 枪管 / 枪口制退器 |

### 2.2 从"体块"到"作者化路径"：硬边 + 破口

- 用 `Path2D`（或 `beginPath` + 贝塞尔）把每个部件写成**闭合路径**，而不是椭圆叠加。路径可以带**破口/撕裂的锯齿边**——这一条在俯视剪影上极其提气，而且是"手工感"的主要来源。
- **硬描边**：现在靠 `tintSilhouette` 烘了一层八向深描边（这个思路是对的，保留），但内部体块之间没有分离。建议**每个体块自带一圈更暗的收边**，让"肩是肩、臂是臂"在小尺寸下也分得开。
- 渐变只留**一处**：顶面受光方向（左上）。现在的 radial 渐变满地都是，导致"处处都在发光、处处都不亮"。

### 2.3 明度分层：比颜色重要得多

给一张角色贴图定义固定的**四级明度带**（现在只有一级）：

1. 描边（最暗，L≈8）
2. 暗面 / 体块分离面（L≈30–40）
3. 中间调（L≈55–70）—— 面积最大，作为基准
4. 顶面亮部 + 冷色边缘光（L≈110–140）—— 面积最小，但决定"立体感"

再叠**一个**强调色（高饱和）：主角=橙红围巾/臂章，僵尸=伤口/眼睛/孢子。**强调色只出现在一处**，多了就回到"糊"。

### 2.4 材质：只画看得出走向的东西

- **褶皱**：2–3 条**沿体块走向**的短线（肩到胸、腰到胯），不要随机噪点。
- **破损**：边缘缺口 + 一处**不规则撕裂边**（比"圆边"强十倍）。
- **污渍/血**：**不受光**的高饱和暗红（L 固定，不参与明暗），主要堆在脚部与撕裂处。
- **眼睛**：改成"**眼窝暗块**"，只有精英/Boss 用"发光单眼"。把发光当稀缺资源用。

### 2.5 动画：按"动作态"出帧，不按"朝向"出帧

现在的 4 帧主要是**整身 squash/stretch + 两条腿摆动** → 读起来像"布丁在抖"。建议：

- **躯干保持刚性**（不随步频压扁），改由「肩部反相摆动 + 少量上下 bob + 随速度的前倾」表达行走。前倾是最便宜的速度感来源。
- **动作态单独出帧**（真正需要多帧的地方）：行走 4 帧 / 扑击 2 帧 / 受击 1 帧 / 倒地 3 帧。
- **朝向不需要 8 向**：整体旋转 + 少量朝向形变（冲刺时沿朝向前倾 10–15%）就够。
- **受击形变**是打击感的第一杠杆（见 3.2）。

## 3. 「打得更有感觉」：手感清单（按性价比排序）

美术只解决"看起来对"，打击感要靠反馈。**这一半对"手感"的贡献大于美术**。

| # | 手段 | 现在 | 建议 | 备注 |
|---|---|---|---|---|
| 1 | **受击挤压回弹** | 无 | 沿**伤害方向**压扁 0.07s 再弹回（scaleX 1.25 / scaleY 0.8） | 2D 打击感第一杠杆，成本极低 |
| 2 | **命中停顿分级** | 只按体型（brute/bloater） | 改成**按单发伤害阈值**触发：轻/中/重 → 0 / 40ms / 80ms | 现在"打小兵"完全没停顿 |
| 3 | **命中特效分级** | 火花 + 血，量固定 | 轻：火花 3 个；中：+定向血溅 + 小冲击环；重：+震屏 + 白闪帧 | 每一下都一样重 = 没有层次 |
| 4 | **受击白闪** | 已有 | 保留，但让白闪**沿描边**更强（现在是整身提亮） | |
| 5 | **击杀分级** | 统一"血 + 飘分" | 普通：碎块 + 血雾；精英：**多段爆碎 + 骨片 + 更长停顿**；Boss：已有大爆炸 | 击杀的"分量"要能在 0.2s 内看出来 |
| 6 | **残躯倒地** | 尸体平躺 5s | 先**倒地压扁**（3 帧）再淡出；**踩过会溅血** | 让战场"有历史" |
| 7 | **镜头语言** | 只有 shake | 命中时朝命中点 0.5–1px 的**短促推镜 + 回弹**；连杀时整体 zoom 0.5% | 比单纯震屏高级，也不晕 |
| 8 | **暴击表现** | 只有伤害数字 | 暴击 = 更大字号 + 白闪 + **击退翻倍** + 专属音头 | 让"堆暴击"这件事看得见 |
| 9 | **武器后坐** | 有 recoil | 把后坐做成「枪身后挫 + 手臂跟随 + 枪口上跳」三件套，而不是整根矩形后退 | 现在枪是一根矩形，看不出"后坐" |
| 10 | **音画同帧** | 有 | 开火的"音头"与火焰帧**严格同帧**；连杀音高递增（已有，保留） | |

## 5. 验收标准（可测，不是"我觉得好看了"）

沿用本项目的习惯——**每条都能用脚本量**：

1. **剪影可读性**：把重做后的精灵缩到实际显示尺寸（28–48px），与地面做像素差分，要求「箱内最大色差 ≥ 现在水平」且**明度带数 ≥ 3**（把精灵内像素按明度聚类，要求出现 ≥3 个明显分离的簇）。
2. **俯视一致性**：把同一精灵旋转 0°/90°/180°/270°，要求"最高明度区域"始终位于**左上（受光方向）**——现在正面造型旋转后受光会跟着转，这是俯视游戏里最容易露馅的地方。
3. **受击形变存在性**：采样受击后 0.07s 内包围盒宽高比的变化，要求 > 1.15。
4. **命中分级生效**：同一把枪打不同血量目标，采样顿帧次数与特效数量，要求随伤害分级单调递增。
5. **不回归**：smoke 现有 87 项、weapon-swap 10 项全绿；`TTK` 不变（美术/特效不得偷偷改数值）；perf 用**同一显式场景**对照（见 `.zcode-smoke/perf.mjs` 的说明）。

## 6. 需要你拍板的取舍

方案分两条路，**成本和上限差别很大**，请您选：

**路线 A：保持零素材（推荐先走这条）**
- 全部程序化生成，继续满足 README 的「无任何图片/音频文件」。
- 能达到的质量上限：**风格化扁平 / 低多边形 / 硬边剪影**（类似《迷你地铁》《Downwell》那种克制但有品味的做法）。
- 代价：做不到手绘质感、做不到像素级精修；细节量受"代码可读性"限制。

**路线 B：引入矢量素材（上限更高，但破坏现有承诺）**
- 允许我把角色做成一批**矢量路径数据文件**（`.js` 里存 path 字符串，仍是零网络请求、零构建），或者直接引入 SVG/PNG 素材。
- 上限：可以做到有手绘感的、真正"设计过"的角色。
- 代价：README 要改口径；素材维护成本上升；且**素材与程序化特效的融合需要额外一轮调**。

**我的建议**：先走 A 的 P0（1–2 小时就能看到主角和三种杂兵的对照），你看到对照图之后再决定要不要走 B。因为 A 的 P0 解决的正是"像表情包/像橡皮泥"这两个最刺眼的问题——那是**造型与视角**的问题，跟素不素材无关。

## 7. 风险与提醒

1. **别在 28px 上追求细节**：这一轮最容易犯的错是"加更多褶皱和花纹"，结果小尺寸下全糊。**先剪影、再明度、最后才是细节。**
2. **发光是稀缺资源**：现在红眼、渐变、边缘光、光晕同时上，视觉重心散了。发光只留给精英/Boss 与玩家武器。
3. **特效分级 ≠ 特效更多**：每一下都重 = 没有层次。分级的意义是让"重的那一下"能被感知到。
4. **改美术不要顺手改数值**：TTK / DPS / 血量曲线这一轮**一律不动**，否则无法判断手感变化来自哪一侧。
5. **必须出图对照**：像素差分断言只能验"画了没有"，验不出"画得难不难看"（上一轮的跃行者爪/腿坐标错位就是只靠放大出图才发现的）。
