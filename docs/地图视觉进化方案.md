# 地图（战场地面）：视觉进化方案

> 起草人：ZCode ｜ 适用版本：`7969221` ｜ 约束同前：**零素材、零依赖、纯 Canvas 2D 程序化生成**
> 相关文档：[美术与手感升级方案](美术与手感升级方案.md)（角色部分已落地 P0）

---

## 0. 一句话结论

现在的地图不是"画得不够细"，而是**做的方式不对**：它是「往一块空地上撒纹理」，
不是「造一个地点」。具体是三件事：

1. **形态上是一堆可辨认的椭圆** —— 3 倍放大图里能一眼追出每个椭圆的边界，读起来是"泡泡/油渍"，不是材质。
2. **尺度是断的** —— 50–300px 的大椭圆、1–2.6px 的头发丝裂缝、1–2.6px 的均匀散点，中间那一档（板块、碎屑堆、车辙）完全缺失。
3. **没有任何"地点信息"** —— 没有地标、没有结构、没有边界、没有用途痕迹；而且**色相与明度都被压在一小段里**（详见第 1 节实测）。

结论：**先定地点 → 再建多尺度结构 → 最后才是纹理颗粒**。顺序反了就会一直"撒纹理"。

## 1. 现状诊断（实测数字 + 代码证据）

取证工具：`.zcode-smoke/map-closeup.mjs`（空场地实拍 + 地形 3 倍放大）、
`.zcode-smoke/audit.mjs`（像素统计，带确定性随机，可复现）。取证图：`shots/map-bare.png`、`shots/map-zoom.png`。

### 1.1 形态：能被眼睛追出椭圆边界
`buildGround()` 第 3–4 步一共画了 **24 个暖土斑 + 38 个大块明暗**，全是
`g.ellipse(rand(0,W), rand(0,H), rand(90,300), rand(55,190), rand(0,3.2))` 这种随机椭圆，
alpha 0.05–0.15 叠上去。半透明大椭圆互相叠加时，**边界在叠加处会显影**，于是画面里是一堆
可辨认的"泡"。这就是"丑"的第一来源 —— 不是颜色问题，是**形状可被识别为几何图形**。

### 1.2 尺度断裂：只有超大与极小，没有中景
| 尺度 | 现在有什么 | 问题 |
|---|---|---|
| >300px | 大椭圆底色、环境光渐变 | 只有明暗，没有"结构" |
| 50–300px | 暖土斑、大块明暗（都是椭圆） | 形状可辨认、彼此无关 |
| 20–60px | **几乎没有** | ← 缺的就是这一档：板块、接缝、碎屑堆、车辙 |
| 1–3px | 420 个碎屑粒 + 46 个反光点 + 裂缝（1.0–2.6px） | 均匀散布 = 噪点；头发丝裂缝与巨型椭圆并置，尺度对不上 |

### 1.3 明度：全挤在暗部，且没有任何高光
`audit.mjs` 实测：
- 地面均值 **38.9/255**，压死黑（<16）7%，**高光（>200）0%**
- 全场景 16 级亮度直方图：`8 37 25 13 8 5 3 1 0 0 0 0 0 0 0 0`
  → **最暗 4 格占了 83%**，第 8 格之后全是 0

含义：地面只有"暗"和"更暗"，**没有中间调层次，也没有任何反光/光斑**。
水膜、灯光池、湿沥青的高光一个都没有 —— 这是"平、脏、廉价"的核心。

### 1.4 色相：所谓"冷环境光"在数据上几乎不存在
- 色相 12 段分布：`15 27 25 11 10 8 4 0 0 0 0 0`
  → 前 3 段（红/橙黄/黄绿）占 **67%**；**青、蓝、紫三段全是 0**
- 地面主色是 `#1c1c14 / #141414 / #24241c`（近中性暗橄榄），颜色数只有 **254**

`PAL` 里确实写了 `ambientTop: rgba(74,116,168,0.26)` 想营造月光冷调，但它是一次性铺满全屏的
线性渐变、又被 24+38 个大椭圆盖住，**最终在直方图里查不到**。冷暖对比没做出来，画面就只剩"灰糊"。

### 1.5 没有任何"地点信息"
- 没有地标：全场没有一处独一无二的东西可以当参照物 → 玩家没有方位感
- 没有结构：看不出这是室内/室外、什么地面、做什么用的
- 没有边界：僵尸从"屏幕外"无限涌来，而地面并没有交代"外面是什么"、也没有围栏/墙/落差
- 没有用途痕迹：没有停车位、车道、排水、装卸区这类"人用过"的痕迹

一句话：**它不像一个地方，只像一块有噪点的地垫。**

### 1.6 等距网格读起来像坐标纸
`buildGround()` 第 8 步画了 **64px 等距网格**（`PAL.grid = rgba(255,255,255,0.020)`）。
虽然只有 2% 白、非常淡，但**等距直线是"人造参考线"的语言**，在大屏上会被读成瓷砖缝/坐标纸，
是"调试感"的来源。地面上的直线应该来自**板块接缝**（不等距、有错位、角度略有偏差）。

### 1.7 雾是"屏幕空间"的，和地面没有关系
```js
const fgx = ((now * 11) % (W + 620)) - 310;      // 横向扫过屏幕
const fgy = H * 0.38 + Math.sin(now * 0.35) * 26;
ctx.drawImage(SPR.fog, fgx - 340, fgy - 230, 680, 460);   // alpha 0.032
```
两层雾都在**屏幕坐标**里横向漂移（另一层 `hz = ((now*15) % (W+780)) - 390`）。
玩家移动时雾**不跟着地面动** → 读起来不是"空气", 而是一层贴在镜头上的薄纱。
（顺带：alpha 0.026/0.032 极低，实际存在感很弱。）

### 1.8 结论
现在的做法是"给空地撒纹理"：随机椭圆给明暗、随机点给颗粒、等距线给尺度感。
**它缺的是"设计"这一步** —— 先决定这是什么地方，再决定这个地方有哪些结构，
最后才用噪声去表现材质。

## 2. 技术路线：把"噪声场"改造成"地点"

> 原则：**尺度分层 → 每层都要有方向性 → 用确定性噪声替代随机椭圆 → 光与影给结构**。
> 全部保持零素材、一次性烘焙（不增加逐帧开销）。

### 2.1 第一步：给场地一个身份（identity）
提案：**雨夜 · 城郊废弃停车场 / 加油站前广场**。理由：与现有的"冷月光 + 暖土斑 + 湿地反光 + 暗角"
气质最连贯，而且它的元素天然自带结构（板块、划线、排水、车辙、车、灯）。

身份决定了要画什么：
- 湿沥青板块 + 接缝（主结构）
- 褪色的停车位划线 / 车道虚线（人造痕迹，给出方向与尺度）
- 雨篦子、排水沟、井盖（点状地标 + 圆形母题，打破全椭圆的重复）
- 车辙、油渍、积水洼（有机形状，带反光）
- 掉落的路锥、废轮胎、购物车、碎玻璃（碎屑，按块聚集而不是均匀撒）
- 远处路灯的光池（光照层次）

### 2.2 多尺度结构：每一档都要"有方向、有对齐"
| 尺度 | 画什么 | 关键约束（这是"不像噪点"的原因） |
|---|---|---|
| **macro ≥300px** | 用地块划分代替随机椭圆：3–5 块**不规则多边形**（沥青板 / 裸土区 / 积水区） | 边界是**折线**不是圆；每块内部明度统一 |
| **meso 20–150px** | 板块接缝（沿 macro 边界走）、补丁、裂缝网、油渍、水洼（有机形状 + 高光） | 接缝**互相平行或垂直**（同一"浇筑方向"）；裂缝沿接缝起、**不穿块** |
| **micro 1–6px** | 骨料颗粒、砂砾、水膜细高光 | 只在暗/中/亮三档里各取一色，密度**随明度变化**（亮处颗粒更密） |

**核心规则**：同一尺度内部必须有**共享的方向或对齐关系**（接缝平行、裂缝沿缝、车辙同向）。
现在所有元素都是"随机角度 + 随机位置"，这是"噪点感"的根源。

### 2.3 明度与色相重做（带具体目标）
- **明度带**：从"1 档"扩到 **3 档**（暗 20–30 / 中 36–50 / 亮 56–72），比例约 35% / 45% / 20%
- **对比度预算（不能破坏剪影）**：地面整体仍必须**比实体暗、比实体低对比**；
  但**允许局部高光**（水膜、光池反光）—— 这是"不廉价"的关键。目标：高光（>200）从 **0% → 0.3–1.5%**
- **冷暖成块**：冷色（阴影/水膜/月光）与暖色（灯池/锈迹/土）要**按区域成块**，
  而不是全屏均匀混合。目标：色相青/蓝/紫三段从 **0% → ≥8%**
- 饱和度的用法：**低饱和打底 + 少量高饱和点**（血迹、锈、玻璃反光），而不是整体加饱和

### 2.4 光与影：这一条最便宜、也最"高级"
- **烘焙一张静态光照图**（一次性，与地形同尺寸）：几处路灯/远处火光的光池 + **环境遮蔽（AO）**：
  板块接缝、物件底部、裂缝内侧压暗。AO 是"结构感"的最大来源之一，且完全可预计算
- **动态光只做加法**：枪口、火焰、爆炸在地面叠加暖光池 —— 现成机制（`SPR.key` / `SPR.glowWarm` 用 `lighter`）
- **统一光源方向**（左上）：地面纹理的受光/背光、实体投影、边缘光全部遵守同一方向。
  现在地面纹理**没有方向性**，这是"平"的主因。有了方向，同一片噪声也会立刻有体积

### 2.5 边界与"世界之外"
- 场地画一圈**边界物**：围栏 / 集装箱 / 废车 / 防洪沙袋。它同时解决三件事：
  ①解释"僵尸从外面来"；②给出方位参照；③让"地图到屏幕边就没了"不再突兀
- 边界外再给一层**远景带**（屋顶剪影、树影、雾中灯），低对比、几乎不动 —— 深度感立刻不同

### 2.6 会变化的地面（让地图参与战斗）
已有贴花机制（血迹/焦痕/弹壳，`addStain` → 烘焙进 `ground`，按年龄淡出）**完全够用**，直接扩展内容：
- **碾压痕 / 脚印**：随移动路径留下，淡出（冲刺会拖出一道）
- **水洼涟漪**：爆炸、冲刺、Boss 震地经过积水时触发
- **燃烧残留**：燃烧瓶留下焦痕 + 余烬亮点（现在是纯焦痕）
> 这些**不增加逐帧开销**，仍走"贴花烘焙进 `ground`、每秒重建一次"的老路。

### 2.7 技术实现与预算
- **分层画布**（现有结构只需加一层）：
  `groundBase`（地形，一次性）→ `ground`（+贴花，秒级重建，机制已有）→ **新增 `lightBake`**（静态光+AO，一次性+尺寸变化时）
  逐帧仍然只 blit 2 张（ground + lightBake），再叠动态光 ✓ 不增加逐帧成本
- **用确定性噪声替代随机椭圆**：带种子的 value noise（2–3 个倍频）天然是**多尺度**的，
  而且不会有可辨认的"圆"。`audit.mjs` 已经演示了确定性随机（`Math.random` 换成 LCG）的做法
- **地块划分**：小规模 Voronoi / 手工多边形表（10 个点左右），一次算好当遮罩
- **别逐像素算**：噪声在 **1/2 或 1/4 分辨率**生成，再放大绘制（地形是暗底，放大看不出）
- **预算红线**：`buildGround()` 现在 **~8.1ms/次**（一次性）→ 目标 ≤3 倍；
  `render` **~9.5ms/帧** 不允许增加（用同一显式场景对照，见 `perf.mjs` 里的说明）

## 3. 分期落地

### P0（先做，1–2 小时，收益最大）
1. **干掉"大椭圆堆"**：24 个暖土斑 + 38 个大块明暗 → 换成 **2–3 个倍频的确定性噪声** + **地块折线划分**
2. **补上中景**：板块接缝（平行/垂直、不等距）+ 裂缝改沿缝走向
3. **去掉 64px 等距网格**，改成板块接缝
4. **明度扩到 3 档**，并按 2.3 的比例配比
5. **加 2–3 处静态光池 + 基础 AO**（接缝与物件底部压暗）

### P0（已试做，2026-09-10）—— 结果与一个量化权衡

**已落地**：随机预制区块拼接（沥青 / 水泥板 / 裸土 / 积水 / 碎屑，`CHUNK_SIZE = 300`）、
用多倍频 value noise 替代随机椭圆、沿单一"浇筑方向"的**不等距**接缝、裂缝沿缝走、
**删掉 64px 等距网格**、每块自己的颗粒层、3 处静态光池 + 亮芯、场地边缘压暗。
全部走**确定性种子**（`TERRAIN_SEED`），同一尺寸下地形可复现（视觉回归可对照）。

**实测（`audit.mjs`，该工具的基线三次运行完全一致，可复现）**：

| 指标 | 改前 | 改后 | 结论 |
|---|---|---|---|
| 压死黑（<16） | 7.0% | **0.1%** | ✅ 明显改善 |
| 地面直方图最暗 4 格占比 | 83% | 89% | ❌ 未达标（目标 ≤60%） |
| 地面高光（>200） | 0% | **0%（峰值 0.1%）** | ❌ 未达标（目标 0.3–1.5%） |
| 色相青/蓝/紫占比 | 0% | **0%** | ❌ 未达标（目标 ≥8%） |
| 地面颜色数 | 254 | 173（中间版本曾到 400） | ❌ 未达标（目标 ≥800） |
| **实体分离比**（normal / brute） | 3.34 / 3.05 | **3.39 / 3.11** | ✅ 红线守住 |
| 实体边界内阶（normal / brute） | 73.1 / 61 | **78.9 / 72.9** | ✅ 反而更好 |
| `buildGround()` 一次性 | 8.1ms | **22.7ms（2.8×）** | ✅ 在 ≤3× 预算内 |
| `render()` 逐帧 | 9.48ms | 9.35ms | ✅ 不增加 |

**关键发现：地面明度与实体分离比是直接冲突的，这是量化过的权衡，不是"没调好"。**
实测曲线：
- 地块填充偏亮 → 地面均值 37.9、颜色数 400，但**实体分离比掉到基线以下**（normal 3.34→3.07、brute 3.05→2.80）。
- 把地块压暗到地面均值 31–34 → 分离比回到 3.39 / 3.11；同时**把烘焙描边从 1.6px 加粗到 2.6px**，
  「边界内阶」从 73.1 提到 78.9。代价是地面变暗、颜色数降到 173。

**因此下一步的正确杠杆是**：
1. **不要用压暗地图去换对比度** —— 那条路会同时牺牲本方案想要的"明度分层"。
   优先加强**实体自身**的分离（描边 / 接触阴影 / 边缘光，已验证有效）。
2. 明度与色彩的提升要放在**不抬高地面均值**的地方：装饰物（废车/围栏/路锥/灯柱）、
   远景带、以及**局部**高光（积水镜面、灯光池亮芯），而不是整体抬亮地块。
3. 「色相青/蓝/紫 ≥8%」这条目标值得重新评估：在夜场景里 8% 的蓝紫会让画面像蓝光房间，
   更合理的做法可能是**把冷色集中在积水与阴影里成块出现**（视觉上够，但直方图上不会到 8%）。
   这条要由你定，我不建议为了凑指标把整场染蓝。

## 5. 需要你拍板的取舍

1. **地图是固定设计还是每局随机？**
   - 固定（手工设计唯一场景）：能做足"地点感"，但重玩时失去新鲜感
   - 随机生成：保持重玩性，但很难做出"这地方我认得"的感觉
   - **折中（推荐）**：随机组合**预制区块**（如 6–8 种区块随机拼接），兼顾两者
2. **装饰物要不要挡路？**
   - 纯装饰最安全，零平衡风险
   - 能挡僵尸 = 有战术价值（可以绕着废车打），但**现在僵尸是直线追击、没有寻路**，
     要挡路就得先加避障，否则会出现"僵尸卡在车后面"——这是个不小的工程
   - **推荐先纯装饰**（视觉收益 100%，风险 0），挡路留到以后单独评估
3. **天气选哪个？**
   - **雨夜（推荐）**：湿反光 + 灯光池 + 积水，最容易出效果，也最贴合现有配色
   - 干夜：省事，但地面缺少高光与反射，"高级感"少一半

## 6. 风险与红线

1. **红线：不能为了地图好看牺牲实体可读性。** 地面一旦变复杂/变亮，僵尸和子弹就会"沉进去"。
   每轮改动**必须**跑 `audit.mjs` 的「实体可读性」那一段，**分离比下降就回退**。
2. **别用"更多细节"解决"不好看"**：地面在 1280×860 上是整屏位图，细节堆多了只会变脏。
   这一轮的主角是**结构（尺度分层 + 方向性）与光（明度带 + AO + 光池）**，不是花纹。
3. **不要增加逐帧成本**：所有地形与静态光都必须烘焙。逐帧只允许 blit + 动态光叠加。
4. **等距网格要清掉**：等距直线=人造参考线的语言，是"调试感/廉价感"的直接来源。
5. **雾必须世界空间**：屏幕空间的雾在玩家移动时会暴露"这是贴着镜头的一层纱"。
6. **改完必须出图看**：像素断言只能验"有没有变"，验不出"难不难看"（角色那一轮就是靠 6 倍放大图
   才发现爪/腿画到画布左边缘的）。地图同理：`map-closeup.mjs` 的空场地实拍 + 3 倍放大是基本动作。
